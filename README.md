# 净元 Metadata Cleaner（公开源码）

这是基于 v1.8.17 整理的公开源码。包含 Electron 桌面客户端、Python 服务端、BS 管理界面及测试。此仓库不包含公司部署配置、数据库、用户记录、日志、账号密码、签名私钥、依赖目录或安装包。

## 使用前配置

仓库中的地址均为示例，不指向原有公司服务器：

- 客户端内网入口：`http://192.168.10.10:8787`
- 客户端外网入口：`http://203.0.113.10:8787`（文档保留地址，不可用于实际连接）
- Docker 默认仅绑定 `127.0.0.1:8787`

部署前请在 `desktop/server-url.js` 中填写自己的内外网入口，并在 `desktop/update-config.json` 中设置自己的更新服务地址。界面中的默认值也应按需修改：`desktop/index.html`、`desktop/login.html`、`desktop/renderer.js`。修改后重新打包客户端。公网使用 HTTP 会明文传输请求；建议配置 HTTPS。若采用同一服务的内外网双入口，必须保证两个入口返回相同的 `server_instance_id`。

`desktop/update-config.json` 保留了更新验签**公钥**，它不是私钥。自行发布更新时，需要生成自己的 Ed25519 密钥对，替换客户端公钥，并仅在受保护的部署环境保存私钥。不要将私钥提交到 GitHub。

## 启动服务端

1. 复制 `server/.env.example` 为 `server/.env`，填写本机绑定地址、端口和域名。
2. 在 `server/secrets/admin_password.txt` 中填写管理员初始密码；此文件由 `.gitignore` 排除。不要使用示例密码。
3. 在 `server` 目录运行 `docker compose up -d --build`。
4. 查看 `http://你配置的地址:8787/api/health`。SQLite 数据保存在 Docker 命名卷 `cleaner_data`，不要将数据卷导出进仓库。

如需让局域网设备访问，可设置 `APP_BIND_IP` 为自己的服务器网卡地址；`server/compose.lan.example.yaml` 是覆盖配置示例。公网端口转发、HTTPS 和防火墙由部署者自行配置。不要在同一项目下创建第二份数据库。

## 客户端开发

在 `desktop` 目录运行 `npm ci`，然后运行 `npm test`。启动开发版使用 `npm start`。Mac 和 Windows 的打包依赖本机平台工具与 Python 文件处理组件，详见 `tools/` 和 `.github/workflows/build.yml`。构建产物位于 `desktop/dist`，不会提交。

## 数据与反馈

联网并登录后，服务端会收到并保存以下信息：

- 账号显示名、设备 ID、电脑名称、客户端版本及最近在线状态；服务端还记录连接来源 IP，以及客户端主动上报的网卡 IP / MAC。
- 清理批次的扫描、处理、失败和字段数量、任务类型、策略版本。为统计每天去重扫描文件数，客户端会上传本机文件路径的 SHA-256 指纹，不上传完整路径或文件名。
- 文件明细包括文件名、检测到的元数据字段和值、处理状态及清理字段数；对成功处理的支持格式图片，客户端会尝试上传一张最长边 640 像素、JPEG 压缩的小预览图。原图内容不会上传，仍留在本机。明细仅供 BS 管理员查看。
- Docker / HTTP 访问日志会记录来源 IP、请求路径、时间和状态码。日志是否保留多久由部署者的 Docker 日志配置决定。

文件路径、完整扫描历史和待同步队列也保存在客户端本机。当前没有自动收集点击行为、崩溃报告或自动发送用户意见的功能；遇到问题需用户主动反馈错误提示、客户端版本和复现步骤。分享日志或截图前，请先检查其中的用户名、电脑名、IP、文件名、元数据文字和本机路径。

## 服务端关键词策略

管理员可在 BS 的“设备与策略”页面选择软件来源清理方式：默认“清理所有软件来源信息”会清除软件/工具来源及文档派生字段，不依赖产品名称词表；普通作者/Creator、描述和版权等个人字段不会被当作软件来源字段清除。也可切换为“仅清理匹配关键词的信息”，自行填写关键词（逗号或换行分隔），匹配不区分大小写。两种方式均不会把普通描述、作者署名或版权字段当作软件来源信息。策略保存后由客户端心跳同步，离线设备联网后同步。

## 发布前自查

确认提交内容不包含 `.env`、`secrets/`、`data/`、`backups/`、`releases/`、`node_modules/`、`desktop/dist/`、`desktop/bin/`、数据库、日志、安装包或用户文件。推送前可运行 `git status --short` 和 `git ls-files` 逐项查看。若曾把真实凭据推送到远端，应立即轮换凭据；仅删除新提交中的文件不能清除旧提交历史。
